# Airflow DAG Integrity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add read-only Airflow DAG integrity checks, operator mock validation, run tracking, tracked job execution, and AWS-tab Airflow UI coverage.

**Architecture:** Follow the established S3/Glue/Athena pattern: a runtime resolves saved configs and explicit overrides, a service wraps read-only Airflow API/client operations and normalizes DAG/run data, routes expose ad-hoc operations, and `RunExecutor` maps tracked-job outcomes into `ReconciliationResult`. The UI enables Airflow while keeping all actions read-only. Tests use fake clients and mocked Playwright routes because there is no live Airflow service in Docker Compose.

**Tech Stack:** Python 3.11+, FastAPI, pydantic v2, SQLAlchemy, pytest, vanilla JS + Alpine.js frontend, Playwright. Use the existing dependency set only.

## Global Constraints

- Add Airflow connectivity/runtime support using saved config fields or explicit Airflow connection params.
- Add ad-hoc Airflow API routes for DAG list, DAG detail, DAG integrity check, operator mock validation, and run status lookup.
- Add tracked job types for DAG integrity, operator mock validation, and run tracking.
- Enable the Airflow AWS sub-tab with ad-hoc checks, result rendering, and tracked-job creation.
- Preserve existing S3, Glue, and Athena behavior and UI state isolation.
- Cover the feature with unit, route, executor, smoke, and mocked Playwright tests.
- Do not mutate Airflow, add Docker services, run live Airflow tests, parse Python DAG source code, implement a scheduler/executor mock, or replace existing project scheduler/history behavior.
