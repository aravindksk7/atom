# Web UI Tab Layout Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the Contracts, File Servers, and Help tabs rendering at the bottom of the viewport, default the Contracts examples panel open for empty accounts, and repair layout/markup defects found across the remaining tab partials.

**Architecture:** The web UI is a single Alpine.js page. Each tab's markup lives in `frontend/partials/tab-<name>.html` and is stitched into `frontend/index.html` by `scripts/build-html.js` at `<!-- INCLUDE: partials/<file>.html -->` markers in `frontend/index.template.html`. Three tab markers currently sit after `</main>`, so those tabs fall outside the `flex:1` main column and get pushed to the bottom with no width cap or padding. The fix moves those markers inside `<main>` and adds a build-time guard so it cannot regress. Remaining tasks repair per-tab defects: one broken HTML attribute, one missing persistent header, and a set of lists that render nothing when empty.

**Tech Stack:** Alpine.js 3 (`x-if`, `x-show`, `x-for`, `x-data`), Tailwind CSS 3 (prebuilt into `frontend/vendor/tailwind.css`), hand-written CSS in `frontend/styles.css`, Node build script `scripts/build-html.js`, Playwright for e2e (`npx playwright test`).

## Global Constraints

- **NEVER hand-edit `frontend/index.html`.** It is generated. Edit the partial or `frontend/index.template.html`, then run `npm run build:html`. CI fails if the committed `index.html` differs from a fresh build.
- After ANY change to `frontend/index.template.html` or any file in `frontend/partials/`, run `npm run build:html` and commit the regenerated `frontend/index.html` in the same commit.
- Do NOT add code comments unless the surrounding code already carries an explanatory comment in that exact style.
- Preserve existing `data-testid` attributes exactly. Playwright specs select on them. Adding new ones is fine; renaming or removing is not.
- This repo checks out CRLF (`core.autocrlf=true`). `scripts/build-html.js` already detects and preserves the template's line endings — do not "fix" line endings.
- Empty states use the existing shared markup shape: a `card empty-state` wrapper containing `empty-state-icon`, `empty-state-title`, and optionally `empty-state-sub`. These classes are defined at `frontend/styles.css:617-624`.
- Scope is defect repair only. No visual redesign, no color/spacing normalization, no new features.
- Do NOT touch: `tab-compare.html:1`'s `compare-tab-container` class (load-bearing for `tests/e2e/38-live-docker-aws-compare.spec.ts:6`), `tab-launch.html`'s `currentView === 'jobs'` gate, or `tab-launch.html:1723-1768`'s deliberately out-of-root CI modal.

**Files:**

- Regenerate: none (this task does not change HTML output)

**Interfaces:**

- [ ] **Step 3: Add the placement check**

In `scripts/build-html.js`, add this constant next to the existing regexes (after the `INCLUDE_SNIFF_RE` definition at line 26):

```javascript
// Tab partials must render inside <main class="main-content">. That element is
// the flex:1 child of the .app-content column, so a tab marker placed after
// </main> renders as a later sibling: pushed to the bottom of the viewport and
// stripped of the 1280px cap, centering, and padding. Overlays (modals, toasts,
// drawers) legitimately live outside <main> and are not tab partials.
const TAB_PARTIAL_RE = /^partials\/tab-.+\.html$/;
```

Then, inside `build()`, immediately after the `const lines = template.split(/\r\n|\n/);` line (line 33), insert:

```javascript
  const mainOpenIdx = lines.findIndex((l) => l.includes('<main class="main-content">'));
  const mainCloseIdx = lines.findIndex((l) => l.includes('</main>'));
  if (mainOpenIdx === -1 || mainCloseIdx === -1 || mainCloseIdx < mainOpenIdx) {
    throw new Error(
      'Could not locate a well-formed <main class="main-content"> ... </main> ' +
      `block in ${TEMPLATE}. Tab partial placement cannot be validated.`
    );
  }
  const misplaced = [];
  lines.forEach((line, idx) => {
    const m = line.match(INCLUDE_RE);
    if (m && TAB_PARTIAL_RE.test(m[1]) && (idx < mainOpenIdx || idx > mainCloseIdx)) {
      misplaced.push(`${m[1]} (template line ${idx + 1})`);
    }
  });
  if (misplaced.length) {
    throw new Error(
      `Tab partial INCLUDE marker(s) outside <main class="main-content"> ` +
      `(lines ${mainOpenIdx + 1}-${mainCloseIdx + 1}): ${misplaced.join(', ')}. ` +
      `Tabs placed after </main> render at the bottom of the viewport with no ` +
      `max-width or padding. Move the marker inside <main>.`
    );
  }
```

Expected: FAIL. Error message contains `Tab partial INCLUDE marker(s) outside <main class="main-content">` and names `partials/tab-file-servers.html` with its template line number.
