ATOM ETL Test Framework reconciles what left the source against what landed in the target — across databases, SAP BusinessObjects reports, REST APIs, AWS lakes and flat files — then enforces quality rules, opens contract breaches when an SLA slips, and hands CI a pass/fail verdict. One FastAPI service, one browser tab, no CDN dependency in production.

01

What the team touches

frontend/ · Alpine.js 3 SPA · Chart.js · pre-built Tailwind · 15 tabs · zero external calls

Connect the environments

Config tab · features/config.js

One saved config holds many named DB connections (hr_db, finance_db…) plus that environment's BO, SAP DS and Automic settings, and named REST endpoints with their own auth mode.

Passwords, API keys and bearer tokens are Fernet-encrypted at rest via WEBHOOK_ENCRYPTION_KEY — transparent to every API consumer.

Launch a test run

Launch tab · job selections · sequences

Pick a config, a source/target environment pair and a saved job selection; validate queries with a dry-run EXPLAIN before spending a run.

Sequences chain selections with preconditions and conditional branches (api/routes/sequences.py). Dual-environment launches run both sides and pair the results.

Watch it live

Monitor tab · Server-Sent Events

Subscribes to GET /api/runs/{id}/stream for step-by-step progress, with automatic fallback to 5-second polling when SSE is blocked by a proxy.

Cancel is cooperative: POST …/cancel sets a flag the executor checks between steps, so the current step finishes cleanly.

Compare anything to anything

Compare tab · features/compare.js

Ad-hoc comparison of SQL ↔ SQL, BO report ↔ file, REST ↔ REST, stored run ↔ production HTML report, a whole folder of files, or the Matrix any-to-any mode that pairs two different technologies.

Backed by compare_service.py (~51 KB) and difference_export.py. Multi-File reuses the pairing logic without a saved job; Matrix can be persisted with Save as Job (compare_type: "matrix") so it schedules like any other job.

Evidence & trends

History · Differences · Reports tabs

Full run history with baseline pinning, run-vs-run diffs (improved / regressed / added / removed), σ-based drift trends, mismatch distribution and per-segment drill-down.

Sub-tabs surface the lineage DAG, column profiles, schema snapshots, the coverage matrix and flaky-job scores.

Contracts & accountability

Contracts · Scheduler Reports · Logs

Named data contracts with an owner, consumers, SLA hours and a semantic version; live OK / BREACHED / OVERDUE badges and inline version bump.

One click runs the ODCS test suite for a contract; Scheduler Reports gives telemetry-backed schedule summaries, failure filters, timelines and exports.

Browse the source systems

Adapters · AWS tabs · features/adapters.js

Log on to BO and browse documents, prompts and instances; look up Automic and SAP DS jobs; test and preview a REST endpoint — then turn any of them into a saved job in one modal.

The AWS tab runs ad-hoc S3 metadata, row-count, partition and format checks, and promotes them to tracked jobs. The Config tab's API exchange inspector shows the redacted request/response pair.

Answers without leaving the app

Help tab · help-content.js · Home tab

A searchable in-app help center documents every tab, option and compare mode — including the Matrix source types and comparison settings — so the docs ship with the air-gapped build.

The sidebar groups the 15 tabs into Setup · Execution · Analysis · System, and Home summarises recent activity.

02

The controlled front door

api/main.py · FastAPI · every /api/* route behind bearer auth

Nobody gets in unauthenticated

BearerTokenMiddleware · CORS · GZip

api/middleware/auth.py guards every /api/* path. Tokens are managed as first-class records through /api/tokens.

Middleware order matters: CORS is registered first so Starlette's LIFO stack answers OPTIONS preflights before auth sees them.

One endpoint per capability

api/routes/ · 26 routers

configs · jobs · runs · compare · contracts · schedules · notifications · tokens · audit · coverage · gates · expectations · profiles · schema-snapshots · lineage · selections · sequences · adapters · logs · settings · health · scheduler-reports · aws/s3 · aws/glue · aws/athena · auth.

runs.py alone is ~68 KB — runs, trends, badges, baselines, drill-down, cancel and the test-suite trigger.

Live progress channel

GET /api/runs/{id}/stream · SSE

Pushes step transitions, per-job status and counters as they happen — no polling storm against the database.

The pytest-suite runner reuses the same stream, emitting collected / passed / failed counts from a parsed subprocess.

Self-documenting for integrators

OpenAPI at /docs · Pydantic schemas

Every request/response is typed in api/schemas.py (~51 KB), so the interactive OpenAPI page is always in step with the code.

FastAPI also serves the SPA itself as static files from frontend/ — a single process, single port deployment.

03

The work gets decided here

api/services/ · 48 service modules · business rules, not plumbing

Turns a request into a verdict

run_executor.py · the ~105 KB core

Dispatches all 18 job types: reconciliation (query / multi-file / BO-live / file), api_reconciliation, health_check, freshness, profile, schema_snapshot, cross_job_assertion, dbt_artifact, compare (incl. matrix), bo_report, bo_job, ds_job, automic_job, and the S3 / Glue / Athena checks.

Owns retry with exponential backoff, depends_on topological ordering (upstream failure ⇒ skip), DQ evaluation, and a cancel check after every step.

Runs jobs in the right order

dag_executor.py · sequence_resolver.py

Topological sort over the depends_on graph, then parallel or sequential execution per run settings. The same graph powers the lineage DAG in the History tab.

Sequences layer conditions and preconditions on top (sequence_conditions, sequence_preconditions, sequence_validation).

Explains every difference

compare_service · difference_export · mismatch_export

Normalises two heterogeneous sides into a common frame, aligns them on key columns, then renders the delta as browsable HTML plus CSV/Excel exports.

Handles BO report exports, uploaded files, live SQL, Athena and REST payloads identically once loaded into the frame engine — which is what makes the Matrix any-to-any mode (POST /api/compare/matrix, 202 + background run) possible.

Per-column tolerances, datetime tolerance, case-insensitive and whitespace-normalised columns, and optional column-parallel diffing are shared by every compare endpoint.

Runs on schedule, unattended

scheduler.py · APScheduler cron

Cron-expression schedules with run-now override, started/stopped with the FastAPI lifespan. A 15-minute background job escalates overdue contract breaches.

Telemetry lands in scheduler_telemetry / scheduler_stats and feeds scheduler_reporting and the CLI.

Holds owners to their SLA

contract_breach_checker · contract_tester · gate_service

Post-run hook: a failed source job opens a breach; a passing one auto-resolves it with duration computed; past sla_hours it escalates.

ODCS contract testing: POST /api/contracts/{name}/test evaluates four pillars — schema conformance, quality rules, SLA freshness and consumer compatibility — into a PASSED / WARNING / FAILED report of per-check verdicts.

Write-Audit-Publish gate: POST /api/gates/{job}/evaluate returns PROMOTE or HOLD so an orchestrator can block a staging→production swap.

Tells the right people

notifier.py · signed webhooks

Fire-and-forget webhooks on run.failed, run.passed, contract.breached, .resolved, .escalated.

Optional HMAC-SHA256 signing so the receiver can verify the payload really came from this instance.

04

Where correctness is actually decided

etl_framework/ · reusable library, importable without the API

Row-level reconciliation

reconciliation/engine.py

Key columns, excluded columns, float tolerance, null handling, hash precheck to short-circuit identical sets, and a schema-mismatch policy.

Pluggable backends (pandas / polars), a chunker for datasets bigger than memory, and a SamplingBackend for cheap shadow runs (2 % default).

Data quality rules

reconciliation/dq_engine.py · 36 types

Basic: not_null, unique, row_count_min/max/between, column_mean_between, match_regex, custom_sql, column_min/max_length, value_in/not_in_set, column_contains, date_range, positive/negative_values.

Advanced: completeness_ratio, distinct_count_between, column_sum/std_dev/percentile, column_type_check, column_value_between, cross_column_consistency, pii_mask_check, no_whitespace, referential_check, custom_sql_assert.

Statistical: outlier_zscore / iqr / grubbs, distribution_ks_test, distribution_chi_square, distribution_anderson_darling, hypothesis_test_proportion, anomaly_detection_sigma — each with error/warn severity.

Profiling & drift detection

column_stats.py · segments.py

Per-column null rate, distinct count, min/max, mean, std dev and p25/p50/p75/p95 — stored per run so drift is measurable, not anecdotal.

Profiles also auto-suggest DQ rules and auto-pick low-cardinality segment columns for mismatch drill-down.

Rules as reviewable code

expectations/ · suite.py · schema_compat.py

Export a job's DQ rules to versioned YAML suites under expectations/, review them in a pull request, sync back with POST /api/expectations/sync.

Schema diffs carry a compatibility verdict: full / non_breaking / risky / breaking.

Durable history & reports

repository/ ORM · reporting/generator.py

SQLAlchemy models and repositories (runs, results, mismatches, audit, contracts, sequences) with self-applying startup migrations — new columns and tables are added in place.

Reporting emits themed HTML, metric sidecars, JUnit XML for CI, and per-run / per-job badge SVGs.

Transform logic in isolation

transform_testing/harness.py · TransformCase

Runs a transform SQL statement against in-memory DuckDB fixture tables and reconciles the output against an expected DataFrame — no live database, no network.

Reconciles with the same ComparisonBackend protocol and mismatch semantics production runs use, so a green unit test and a green production job mean the same thing. Examples live in tests/transforms/.

05

The systems being tested

Adapters read only what they need — live mode, or full local simulation

Warehouses & databases

db/engine.py · SQLAlchemy + pyodbc

SQL Server (mssql+pyodbc), Oracle (oracle+oracledb) and Netezza (netezza+pyodbc with a registered dialect shim).

sql_utils.py keeps dialect-specific chunking and pagination correct per backend.

SAP BusinessObjects

sap_bo/client.py · RESTful Web Services

Logon token session, CMS query for report discovery, prompt/parameter handling, schedule & instance lookup, and export of a report to CSV/XLSX for comparison.

The largest single adapter in the tree (~65 KB) — on-prem BO gateways are quirky about paging and answer ordering.

Batch & ETL schedulers

automic/client.py · sap_ds/client.py

Automic job/run lookup (automic_job) and SAP Data Services job execution and status (ds_job) become first-class monitored job types.

A run can therefore assert "the batch finished" and "the data it produced reconciles" in one pass.

AWS data platform

aws_s3/ · Glue · Athena

S3 object metadata, row counts across CSV/JSON/Parquet/ORC (S3 Select for row formats, pyarrow footers for columnar), Hive-style partition discovery, format + schema validation.

Plus Glue catalog comparison and Athena query jobs, sharing one AWSSession.

REST API sources

rest_api/client.py

Named endpoints with none / API-key / bearer / basic auth, JSON dot-path record extraction or CSV, and cursor or page-limit pagination.

api_reconciliation reconciles two endpoints against each other with the same keys, DQ rules and pass conditions as SQL.

Files, spools & SFTP

file_source.py · multi_file_remote.py · file_mapping.py

Compare many files per side: pair by filename token (match_on) or let the automated strategy guess pairs by structural similarity.

Reads local disk, S3 or SFTP, polls for a live spool to finish writing, and runs every matched pair in parallel with per-pair failure isolation.

dbt project artifacts

dbt_artifact_parser.py

Parses run_results.json (optionally manifest.json) and maps dbt test statuses onto normal run results.

Failing and error nodes are recorded as mismatch details, so dbt failures appear in the same History and Contracts views.

Where results live

etl_framework.db · ./logs · ./reports · expectations/

SQLite by default; point ETL_DATABASE_URL at any SQLAlchemy-compatible database for shared deployments. Schema upgrades apply at startup.

Logs and metric sidecars land in ./logs, generated HTML in ./reports, versioned rule suites in expectations/.

Runs through every layer

Access control

Bearer tokens · Fernet-encrypted secrets

Token CRUD via /api/tokens; config secrets (db_password, bo_password, automic_password, REST credentials) encrypted at rest with the same key used for webhook signing.

Audit trail

audit_service.py · GET /api/audit

Every create, update, delete and mismatch-accept records actor, action, resource type, resource ID and a JSON diff — visible in the History tab and queryable by API.

CI/CD gating

runner/cli.py · badges · JUnit

--gate-run <run_id> exits 0 passed · 1 failed · 2 cancelled · 3 error · 4 not found.

Pair with badge SVGs, JUnit XML and the WAP gate endpoint for a pipeline that blocks on data quality.

Observability

utils/logging · tracing · diagnostics

Structured logging configured at startup, optional tracing, a diagnostics service, plus the searchable Logs tab backed by log_parser.py.

One run, end to end

  1. STEP 01

    Trigger

    UI launch, cron schedule, CI call or sequence step.

    All four paths converge on the same POST /api/runs contract, so a scheduled run and a hand-launched run are indistinguishable downstream.

  2. STEP 02

    Resolve & order

    Config decrypted, jobs topologically sorted.

    Environment validation runs first (job_env_validation.py); jobs whose upstreams already failed are marked skipped rather than executed.

  3. STEP 03

    Extract both sides

    Source and target pulled through their adapters.

    SQL, BO export, REST page walk, S3 object or spooled file — each normalised into a common frame before any comparison happens.

  4. STEP 04

    Reconcile & assert

    Row diff, then DQ rules and pass conditions.

    Hash precheck first; on mismatch, key-aligned row comparison produces typed mismatch records, then the DQ engine adds rule violations at error or warn severity.

  5. STEP 05

    Persist & report

    TestRun stored, HTML/JUnit/badges written.

    Results, mismatches, profiles and schema snapshots are written as related rows, so later runs can diff against them and the trend cache invalidates itself.

  6. STEP 06

    React

    Breaches, webhooks, gate verdict, audit entry.

    The breach checker opens or resolves contracts, the notifier fires signed webhooks, and the gate endpoint turns the outcome into PROMOTE or HOLD for the deployment pipeline.
